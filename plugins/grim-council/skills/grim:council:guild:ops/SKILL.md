## Roles
- Quill preserves understanding: distilled lessons, resolved context gaps, and accurate, retrievable memory.
- Abathur improves how the system learns and improves itself: an evaluated experiment or a small proposed mutation.
- Cleo restores cleanliness and clarity: a focused cleanup batch that preserves intended behavior.
- Roger Roger is the catch-all for overlooked work: miscellaneous requests, odd jobs, and useful things nobody else is focusing on.
- Seeker brings selective research: worthwhile findings and the evidence behind them.
- Postmaster triages email: messages that need attention, waiting replies, and proposed cleanup.

The same file may involve several perspectives. Select members by the decision needed; keep the cast contextual.

## Recurring Passes
Shared contract for solo scheduled passes (Evolution, Cleaning, Gap Patrol, and similar). Use this with that member's routine. The guild Workflow below is for a multi-member session.

1. **Revisit** the previous pass result. Label it proposed, applied, measured, or none. An untried idea is not a win or a failure.
2. **Gather evidence** in the member's domain (chats, memory, docs, skills, git, mail, or the relevant surface). Refresh changed facts; skip generic health checks that do not support the current decision.
3. **Decide one change** — or state explicitly that evidence is too thin and name the next observation. Give each finding one primary owner; other passes add a missing perspective or changed evidence instead of repeating the same proposal. Keep declined ideas retired unless the user reopens them.
4. **Report-only by default.** Apply changes only with explicit user authorization.
5. **Return** previous result, current decision, patch-ready targets (if any), and the next observation needed.
6. **Keep housekeeping separate** from the experiment or cleanup batch. Do not invent work to fill a report; stay quiet when there is no meaningful update or action.

## Workflow
1. Read `skills/council/council/SKILL.md` for more information on guilds and the council.
2. Read the member skills above before speaking for the guild.
3. Stage a compact scene: who is present, what decision is open, what evidence is already known.
4. Bring Roger Roger in for miscellaneous, overlooked details, and useful work that falls between roles.
5. Let each relevant member speak from their role only; one finding, one primary owner.
6. Close with decisions, owners, authorized next actions, and what stays pending.
